# Underground Transfer Hub

A mod for Transport Fever 3. The terms are in `CONTEXT.md` and the decisions in `docs/adr/`.

## Layout

The mod has two folders in the staging area of the game, side by side.

| Folder | Holds |
|---|---|
| `kacsa_underground_hub` | The mod as the game loads it and uploads it: `mod.json`, `strings.json`, `content`, `_metadata` and `image_00.jpg`. Nothing else MAY be in it, because the game uploads the whole folder. |
| `kacsa_underground_hub_dev` | The git repository, this README, `CONTEXT.md`, `docs`, `tests` and `tools`. |

The repository tracks both folders: its work tree is the staging area (`core.worktree = ../..`), and `.git/info/exclude` leaves out every other folder there. The `.gitignore` of the staging area belongs to another repository and ignores the mod folder, so a new file of the mod folder needs `git add -f`. A command of this README runs in `kacsa_underground_hub_dev`, unless it says otherwise.

## Overview

The hub builds one to four stacked underground levels. Each level is a two-track platform with side platforms.

## Origin

The mod follows [Simple Underground Transfer Station](https://mod.io/g/transportfever3/m/simple-metro-transfer-station1) (`underground_station_transfer_1`, revision 3, called the source mod below): the design of every level, the strips on the platforms, the cargo depot and the reconfiguration after construction come from it. The source mod belongs to its author, who gave permission to publish this mod.

## Parameters

Every parameter can change after construction.

| Parameter | Choices | Applies to |
|---|---|---|
| Level n vehicle | Level 1: Rail, Tram. Levels 2 to 4: Off, Rail, Tram | One selector for each level. Off removes the level. Level 1 always exists. A level keeps its depth by its number, so level 3 can exist without level 2. The selector of a connected level is hidden, so that no level with tracks can be removed. |
| Operation | Passenger, Cargo, Mixed | Hub. Cargo and Mixed add the cargo depot and open the lanes and terminals to cargo. |
| Track type | Simple and Standard until 1980, Simple, Standard and High-Speed from 1980 | Rail levels. Greyed out when no level is rail, and locked while a rail level has connected tracks. |
| Catenary | No, Yes | Rail levels (catenary on the track) and tram levels (electric tram track). Locked while any level has connected tracks. |
| Level n angle | 0° to 180° in steps of 5° | Level n. A level looks the same after half a turn, so half a circle covers every position. The defaults are 0°, 90°, 45° and 135°. |
| Level n length | 40, 80, 120, 160, 240, 320 m | Level n. A level has two length selectors with the same label: one for rail with the default 240 m, one for tram with the default 40 m. Only the selector of the chosen vehicle shows, and each keeps its own value. |

The game draws a divider between parameter groups: the hub (operation, track type, catenary), and for each level a title, its controls, and a note when it is locked. The dividers above the controls of a level are hidden. The stylesheet `hub_params.css.lua` sets its thickness and colour (yellow, 4 px), the spacing of the list around it, the bold title of a level, and the lock note as red text without a button background. It also narrows the sliders of the settings window to 187 px, so the right side stays free for the scroll wheel, fixes the slider width so its value box sits next to it, and raises the maximum height of that window (a cap, not a fixed height) to 700 px. It names every group that has a divider above it, so a new group needs an entry in that file. A check function returns "Enabled", "Disabled" or "Hidden". The source mod returns true and false, so its controls never grey out.

## Constraints

- The content path is `content/stations/rail/underground_hub/`. It cannot clash with another mod that uses `stations/rail/underground/`.
- The source mod writes its files to `stations/street/underground_station/`. That is the path of the underground station that ships with the game, so it replaces the game's own station. This mod MUST NOT write to that path.
- The hall, stairs and surface building are models of the game station in `stations/street/underground_station/`. Those files belong to the game. This mod ships only the strips (`models/shared/`) and the cargo depot (`models/cargo/`) of the source mod, and the empty model that hides the catenary poles inside a hall.
- A rail level runs its tracks on the floor of the tram hall. The hall model has tram rails baked into its floor, at the same place as the two tracks. The tracks sit 0.3 m below the floor, so that their rails show about 0.24 m above the floor and 0.11 m below the platform edge. A track at floor level hid its rails in the baked tram rails, and a track at -18.0 stood above the platform edge. The two tracks are real railway edges inside a tunnel type without walls, `station_hall.tunnel`. The rail tunnel that joins a hall has a different profile from the hall end. If the join looks wrong in the game, the fix is a transition model.
- The game draws a ballast bed of 0.3 m on every railway edge, also when every model of the track style is empty. The two inert edges of a tram level lie 1 m below the floor of the hall, so the bed does not cover the tram rails of the hall model.
- A tram level has two parallel inert railway edges across its hall, in a track style whose models are all empty, with nodes that are not free. They exist only so that the placement preview draws the length of the hall, as it does for a rail level. Vehicles do not use them.
- The tunnel that joins a rail level to the world is the newest rail tunnel of the game that is available in the year of the station: the rock tunnel before 1970, the concrete tunnel from 1970. The third rail tunnel of the game is hidden by the game.
- The track type has two selectors with the same key, one for each year range, as in the source mod. The panel of a built station ignores the years, so the check function of each selector hides it outside its years.
- The panel of a built station honours only "Hidden" from a check function, not "Disabled". So there a control that is off, such as the controls of a level that is off or of a connected level, and the vehicle selector of a connected level, is hidden, and the red note stays. The panel of a placed station greys the control out.
- A level counts as connected when a track or street that is not part of the station ends on a free node of that level. The game passes no entity to a check function, so the script finds the edited station by comparing the values of the panel with the stored parameters of every station of this mod (ADR 0003). The hidden parameter `hubPlacement` tells a station that is being placed from a built station that is being edited. The nodes of the station come from its edges, because the free nodes at the ends of its tunnels are not frozen nodes. When the panel changes a value, the values match no station any more, and the script keeps using the stations of the last match, so the lock stays while the panel is open. The result is cached for one second. The log line "[hub] lock lookup" shows how many stations and nodes the lookup examined.
- The dummy slot `underground_dummy` makes the game show the configuration wrench. Reconfiguring a built station rebuilds its edges. The game decides what happens to tunnels that connect to an edge that moves or disappears.
- The icon of the menu is the plot of the icon of the source mod, with three levels below it: a rail track, a tram track and a rail track, drawn in the ground plane of the plot. It has no text, because the game does not translate a picture. The files are the uncompressed TGA files `underground_hub.tga` (120 x 75) and `underground_hub@2x.tga` (240 x 150). The preview image `underground_hub_preview@2x.tga` (1600 x 900) is the picture of the cover of the mod page, without the title band. The shared module names both relative to the construction files, which lie in the same folder: a path that starts with `::/` names a file of the game, and the game does not find a file of this mod there.
- The tunnel of a tram level beyond its hall has two pieces of 5 m. The tunnel script of the game closes a dead end with a wall only for a tunnel type that names five dead-end models. The rail tunnels do, the car tunnels name three, so an unconnected tram tunnel stays open and shows the empty space behind it. `tram_end.tunnel.lua` is the concrete car tunnel of the game with five, built by `node tools/build_tram_tunnel.js`. The outer piece uses it and holds the free node, so the game closes its outer end while no street is connected. The inner piece is the tunnel of the game: it ends at the hall, where the tunnel MUST stay open, and it keeps the outer piece from having a dead end there. A tram level has 16 edge nodes.
- The functions of the hub are in the module `hub_script.lua`. Two script files hand them to the game: `station.script.lua` for the check functions and the template, and `stations/street/underground_freight/underground_freight.script.lua` for the update function. Each returns a new table on every call, because another mod may replace a function in the table it gets. The module names every file of this mod with the mod in front, as `kacsa_underground_hub::/stations/rail/underground_hub/...`. The game looks up a name without it relative to a file, and the update function comes from a script file in another folder.
- The second script file makes the mod Cargo Range (`gabri_cargo_catchment_1`) work with the hub, without a change of that mod. That mod finds a station by the path of its update script, without the mod name in front, in a fixed list. `/stations/street/underground_freight/underground_freight.script` is in that list, as a street station that MAY be mixed. With this path that mod adds its range settings to the hub, shows its range card in the station window, and scales the radius of the catchment area after the update function: by the passenger range for a passenger hub, by the cargo range for a cargo hub, and by the cargo range for a mixed hub when "Include mixed stations" is on. It reads the fields `passengers`, `cargo` and `cargoTransferSpeeds` of the terminals and `catchmentAreas` of the station, so these MUST keep their form. A mixed hub has one catchment area for both, as every mixed station of the game. Without that mod the path has no effect.
- The hidden parameter `seed` tells stations with equal values apart. The game stores a random seed with every construction. The parameter can change after construction, so the panel of a built station hands the stored seed to the check functions with the other values, and the comparison of ADR 0003 then matches only the edited station. Its first year is 9999, so the menu of a placed station leaves it out and never sets a seed. Without it, two hubs with equal values lock together, and a slider that passes the values of a connected hub is hidden in the middle of the drag. A station without a stored seed is found by its values alone, as before. The log line "[hub] lock lookup" shows the seed of the panel and the stored seeds of the stations it found.
- The hub has two construction files, one for each menu, because a menu entry cannot give a parameter another default. `station.con.lua` lists the hub under Rail, Buildings, and level 1 starts as a rail level of 240 m. `station_tram.con.lua` lists it under Road, Buildings, and level 1 starts as a tram level of 40 m. Both load the shared module `hub_con.lua` by its name in the game, `kacsa_underground_hub::/stations/rail/underground_hub/hub_con.lua`, and differ in nothing else. A station keeps the file it was placed with. The lock lookup finds the stations of both files.
- The toolbar of the construction menu shows a passenger capacity. The game counts it on the platforms of the default station: cells of 1.2 m along and across the walkway of each terminal. So the road entry shows 128 and the rail entry shows 800.
- The mod page lives in `_metadata/`: `modinfo.json` holds the name, the summary, the description and the tags, `0.png` is the cover, with the icon and the name on a dark band, and `1.png` to `4.png` are the gallery, all 1920 x 1080. `image_00.jpg` is the picture of the mod in the mod list of the game. The name of the mod page is "Underground Transfer Hub for Tram and Rail": the English name of the construction menu and " for Tram and Rail". The first heading of the description repeats it. The name has 42 characters. The wiki advises at most 32, and the validation of the game accepts the longer name.
- The price is the price of the source mod: a maintenance cost of 150,000 for each active level, 1.25 times that in Cargo and Mixed operation, and a build cost of 6 times the maintenance cost. The length of a level does not change the price.
- Two neighbouring levels are joined by stairs (ADR 0005). A passenger who comes down from the ring turns to the platform. After one more turn the stairs down lie ahead, in the corridor wall that faces away from the centre. All four corridors of a level have such an opening. The first flight leads towards the centre, between the wall of the hall and the stairs from the ring, with a real wall of 0.3 m between the two. The two first flights of one platform side meet on a landing above the roof of the lower ring. One free second flight leads from there, in the middle of the hall, down to a shared round platform in the middle of the lower ring, 2.4 m above its floor. Two exit stairs lead from the shared platform to the ring. The stairs replace the shaft of that level. A level below a gap keeps its shaft.
- The exit stairs point to the two exits of the lower ring when that direction lies between the two second flights. That is the case when the exits lie at most 30° from the axis along the upper hall, as with the default angles of 0° and 90°. In every other case, such as two parallel levels, the exits lie below the second flights, and the exit stairs point along the upper hall. Passengers then walk along the ring gallery to an exit. The railing of the shared platform is built from pieces of 5°, so that it leaves the four stairs open at every angle.
- The stairs need models, built by `node tools/build_stair_models.js` from the hall of the game. `hall_doors.mdl` is the hall of the game without the four corridor walls. Every level uses it, and `hall_door_plugs.mdl` puts the walls back on a level without stairs down. `level_stairs.mdl` holds the flights, the landings, the round hall inside the lower ring and the shared platform. `exit_stairs.mdl` and `platform_rail.mdl` are turned by the script. The tool also builds `back_hedge.mdl` from a hedge of the game. The stairs use the materials of the game hall: white walls, the reddish ceiling of the ring, the floor tiles and black handrails. The round hall inside the lower ring is open towards the two landings above a parapet that follows the steps, has green ribs on its white wall that meet beams below the ceiling, a light band around the top of the wall and a round light where the beams meet. A generated model lists only the materials it has faces for, because the game stops with a fatal error on a mesh part without faces. The walkway in `hub_script.lua` and the tool use the same measures, so a change of one needs the other. The game MUST be installed to run the tool.
- The validation of the game allows 256 KB of mesh data in the lowest detail level of a model. The full mesh of `level_stairs.mdl` has 403 KB, so the model has a second, coarse detail level from 300 m on: ramps for the steps, no handrails, no light panels. The tool stops when the lowest detail level of a generated model is over the limit.
- The validation of the game asks for the format DXT1 where a material does not read the alpha channel of a texture. Four materials of the game read five DXT5 textures that way: two hedge materials, the track bed of the hall and the tram paving. The tool writes a copy of each material to `models/mat/` and a DXT1 copy of each texture to `models/mat/tex/`, and `hall_doors.mdl` and `back_hedge.mdl` use the copies. A DXT1 copy keeps the colour part of every block, so its colours are the same bit for bit. The asphalt map of the track bed has 4096 x 4096 pixels in the game. Its copy leaves out the largest mipmap level and starts at 2048 x 2048, so it has 2.8 MB and not 11 MB. Its other levels are the same bit for bit.
- The light panels in the ceilings of the game hall use a street light material, which glows only at night. `models/mat/hub_light.mtl` is the same texture, always on. The copy of the hall, the copy of the entrance building (`surface.mdl`) and the ceilings of the stairs use it.
- The ring gallery of every level has bins and ticket machines of the game along its outer wall, away from its two exits. It has no benches, because it is only 3.15 m wide. Four benches stand at the foot of the shared platform, below the two second flights, where the exit stairs never point. A cargo hub has only the bins.
- The catenary of the tracks inside a hall hangs 5.4 m above the track base, not 6.447 m as on an open track. The ceiling of the hall is 5.8 m above the track base, and the ring gallery lies right above it, so a higher wire shows in the gallery.
- The plot is turned by half a circle, compared with the game station. The street and the open side of the plot lie where the stairs of the entrance building start. The entrance building itself stays, because its stairs lead to the middle of the hub, so the hub lies behind the plot and not below the street. The turn is around a point 0.75 m behind the middle of the plot. This moves the plot 1.5 m back, so the building stands 1.5 m closer to the street, and the street side lies at y = 22.5. The advertising column stands at the back in place of a row of benches, clear of the building. The cargo depot moves to the other side with the turn.
- The hedge models of the game reach 3.4 m below the ground. The stairs of the entrance building pass below the back of the plot, and their ceiling lies only 1.69 m deep there. So the back hedge uses `back_hedge.mdl`, a copy of the game hedge in which every point below 1 m depth is lifted to that depth. The tool builds it. The plot is levelled, so the hedge needs no deeper base. No other hedge stands above the stairs.
- The ground texture of the game plot is a map of 16 by 16 cells: asphalt at the open side and in the middle, grass along the hedges. The script turns it with the plot, by taking the texture coordinates from the face before the turn. Without that, the grass rows of the back lie at the street. A face of plain asphalt covers the part between the hedges, so grass grows only below and behind the hedges. The game blends the ground at the edge of a face, and grass grows about 1 m into the paving there. So a second asphalt face lies in front of the plot, 3 m deep and as wide as the plot. It keeps that edge away from the plot and reaches the pavement of the street. The face names the ground texture `asphalt_01.gtex` of the game. A terrain material (`.tmat`) is not valid there: the game logs "referenced ground texture not found" and ignores the face. The source mod has this defect in its depot apron.
- The game links every node of a linkable lane to the pavement near it. Only three pieces of 1 m at the street side of the plot are linkable: one in the middle and one 4.4 m to each side. Each piece gives one connection to the pavement, and a walkway leads from each to the top of the stairs. The rest of the walkway is not linkable, so people do not walk through the hedges to a pavement beside or behind the plot.
- The walkways are complete inside the script: the entrance stairs, the ring galleries, the passages to the platforms, the stairs between neighbouring levels and the shafts. The game needs no other setup. A test proves that every platform is reachable from each connection to the pavement.
- The loading speed of cargo is the normal speed. The source mod raises it to 200 %; this mod does not.
- The string keys use the prefix `HUB_`, so they do not clash with the keys of other mods.
- `strings.json` covers the 13 languages of the game and is built by `node tools/build_strings.js`. A word that the game has comes from the catalogue of the game (`base/strings/<language>/LC_MESSAGES/base.mo`), so the station uses the same words as the game: the operations, Rail, Tram, Off, Angle, Length and Level n. The tool holds the message id of each such word. Only the name, the description, the name of a new station and the note of a connected level are translated in the tool. The name uses the game's word for a transfer. The label Operation has no word in the game, so the other languages use the game's word for Mode. In Chinese the game's word for Level means a rank, so the level titles there use the word for a floor. To change a text, edit the tool and run it. The game MUST be installed to run the tool.

## Tests

The tests run the construction script against stubs of the game modules. They prove the logic, not that the game accepts a call.

```text
cd ../kacsa_underground_hub
LUA_PATH="../kacsa_underground_hub_dev/tests/?.lua;;" lua55 ../kacsa_underground_hub_dev/tests/hub_test.lua
```

`hub_test.lua` checks several levels (depth, terminals, node and lane indices, shafts), mixed rail and tram levels, the one design of all levels, the platform strips, the cargo modes, the dummy slot, the greying out of controls, the stairs between neighbouring levels and the shaft below a gap, the turned plot with its ground, its hedges and its three connections to the pavement, that every platform is reachable on foot from each connection, that every parameter can change after construction, and that the construction file names only existing functions, models and strings.
